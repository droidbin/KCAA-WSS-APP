## 🚀 주요 핵심 기능 및 아키텍처

### 0. 별도 앱 설정 화면 및 알림 허브 연동 완성 (신규 v1.7.0)
- **네이티브 설정 화면(`settings/`)**: 포털 팝업에 주입하던 설정을 별도 화면(`SettingsActivity`)으로 분리. 알림 / 바로가기 / 관리자 / 앱 / 정보로 나뉘며 웹 페이지 상태·마크업과 무관하게 열림
- **모든 화면에서 진입**: 포털 메인은 헤더 [설정] 버튼, 발주·증명서·법정의무교육·인사관리 같은 모듈 화면은 앱이 띄우는 작은 설정 버튼(위아래로 끌어 옮길 수 있고 위치 저장), 앱 밖에서는 런처 아이콘 길게 누르기 → "설정"
- **새로고침 = 포털 메인으로 이동**: 당겨서 새로고침과 설정의 [포털 새로고침]은 현재 페이지를 다시 불러오지 않고 포털 메인으로 이동 (입력 중인 모듈 화면에서는 입력 내용이 사라질 수 있음)
- **설정 항목 추가 방법**: `settings/SettingsCatalog.kt` 의 해당 `SettingsPage` 에 `Row`(스위치/이동/동작/링크/정보)를 한 줄 더하면 화면 코드 수정 없이 나타남. 새 하위 화면은 `SettingsPage` 를 만들어 `pages` 에 넣고 `Kind.NAV` 행으로 연결. 웹을 움직이는 동작은 설정 화면이 `SettingsContract` 의 고정 액션으로 메인 화면에 요청(임의 주소·스크립트 불가)
- **알림 공용 코드**: 권한 요청·시스템 설정·테스트 알림을 `push/PortalNotifications.kt` 로 모아 메인·설정 화면이 함께 사용
- **기기 알림이 꺼지면 서버 등록 해제**: 서버 `DELETE /api/push/device` 호출, 다시 켜면 새로 등록. 서버가 알려 준 관리자 역할(`unified`/`reader`)을 앱 권한에 반영하고, 오프라인에서는 관리자 권한을 내리지 않음
- **앱 링크 확장**: 발주·증명서 도메인도 앱으로 열리도록 `autoVerify` 링크 추가 (각 사이트 `assetlinks.json` 배포 확인)

### 0-000. 포털 알림 허브 연동 보강 (v1.6.0 범위)
- **종류별 알림 채널**: 공지 / 발주 / 업무요청 / 증명서 / 관리자 채널로 나눠, 기기의 시스템 알림 설정에서 종류별로 소리·표시를 조절할 수 있음. 이전의 단일 채널은 삭제(`push/PortalPush.kt`)
- **알림 주소 검증**: 알림이 여는 주소는 포털·발주·증명서 도메인(https)만 허용하고, 그 외에는 포털 홈으로 대체(`util/PortalHosts.kt`)
- **모르는 알림 종류**: 서버가 새 종류를 보내면 공지 채널로 표시하고 공지 수신 설정을 따름
- **서버 상태 확인**: `GET /api/push/preferences`로 기기가 서버에 남아 있는지 가끔(6시간 간격) 확인하고, 서버가 기기를 지웠으면(FCM 토큰 만료 등) 다시 등록
- **관리자 알림 설정 유지**: 관리자 세션이 끝나도 서버가 기기의 관리자 역할을 유지하는 동안(로그인 후 30일)은 관리자 알림 스위치를 유지하고, 로그아웃하면 바로 숨김
- **등록 오류 안내**: 기기 수 한도(503)·요청 제한(429) 응답을 설정 화면에 안내하고, 요청 제한 뒤에는 10분간 다시 보내지 않음
- **발주 알림 기기 연결**: 설정 화면에서 발주 사이트의 `/orders/notify`(이메일 인증)로 이동해, 다른 기기에서 접수한 발주의 처리상태 알림도 받을 수 있음

### 0-00. 권한별 알림 설정 및 설정 화면 사용성 개선 (v1.5.0)
- **권한별 알림 항목**: 알림 종류마다 최소 권한을 두고(일반직원 < 일반관리자 < 통합관리자), 설정 화면에는 현재 권한으로 볼 수 있는 항목만 만듦. 권한은 포털 관리자 세션(`/api/admin/session`)으로 확인
  - 일반직원: 새 공지 / 발주 처리상태 / 업무요청 답변 / 증명서 수정요청 결과
  - 일반관리자: 위 항목 + 새 발주 접수
  - 통합관리자: 위 항목 + 새 증명서 수정요청
- **빈 구역 숨김**: 볼 수 있는 항목이 없는 구역은 제목과 구분선까지 화면에 만들지 않음
- **권한 밖 항목 미전송**: 기기 등록 요청에 현재 권한으로 다룰 수 있는 알림 종류만 담음(`push/PortalPush.kt`)
- **스위치 반응 개선**: 누르면 바로 바뀌고, 저장하는 동안 다시 누를 수 없으며, 저장에 실패하면 이전 상태로 되돌리고 안내를 표시
- **터치 영역**: 헤더 버튼과 스위치 행을 44px 이상으로 맞춤

### 0-0. 네이티브 푸시 알림 및 설정 화면 스크롤 수정 (v1.4.0)
- **네이티브 푸시(FCM) 수신**: `push/PortalMessagingService.kt`가 포털 서버의 데이터 메시지(`type`, `title`, `body`, `url`)를 기기 알림으로 표시하고, 알림을 누르면 해당 화면(포털 계열 허용 도메인만)을 앱에서 엶
- **알림 종류**: 새 공지 / 발주(요청자에게 처리상태 변경, 일반·통합 관리자에게 새 발주 접수) / 업무요청 답변(요청자) / 증명서 고정값 수정요청 승인 결과(요청자). 설정 화면에서 종류별로 켜고 끌 수 있음
- **기기 연결**: 앱이 만든 무작위 기기 식별값을 포털 계열 도메인에 `kcaa_app_device` 쿠키로 심고, FCM 토큰·수신 설정을 포털 `POST /api/push/device`에 등록(`push/PortalPush.kt`). 서버는 이 쿠키로 "이 앱에서 낸 요청"과 "관리자 로그인 기기"를 구분
- **알림 권한**: Android 13 이상에서 첫 실행 시 알림 권한을 한 번 묻고, 거부한 뒤에는 설정 화면의 [알림 허용]으로만 다시 요청
- **서버 준비 상태 확인**: 기기 등록 응답의 `configured`가 `false`(서버에 FCM 발송 설정 없음)이면 설정 화면에 안내를 표시하고 다음 실행 때 다시 확인
- **Firebase 설정**: `app/google-services.json`이 있을 때만 google-services 플러그인이 적용됨. 파일 없이 빌드하면 푸시만 꺼진 상태로 동작. 서버용 서비스 계정 키는 저장소에 두지 않음
- **설정 화면 스크롤 수정**: 설정 다이얼로그에서 스크롤하면 뒤의 포털 페이지가 움직이던 문제 수정. 다이얼로그가 열려 있는 동안 당겨서 새로고침도 비활성화

### 0-1. 포털 디자인 언어 정렬 및 보안 강화 (v1.3.0)
- **운영 포털 디자인 언어로 전면 정렬**: 운영 포털에 실제 적용된 스타일(흰 헤더, 강조색 `#2563EB`, 배경 `#F6F7F9`, 테두리 `#E4E7EC`, 본문 `#182230`, 회색 아이브로우, 모서리 16/11/10px, `Portal`(Pretendard) 서체)에 맞춰 앱 헤더 주입 스타일·설정 메뉴·로딩/오류 화면·상태바를 재작성하고 이모지를 제거
- **헤더 개선**: 포털과 같은 흰 헤더를 유지하면서 브랜드·버튼을 한 줄로 배치. 관리자 로그인 시 관리자 메뉴가 브랜드를 밀어내던 문제를 수정(아래 줄 가로 스크롤)
- **시스템 바 정리**: 상태바를 포털 헤더(흰색)·페이지 배경색과 맞추고 아이콘은 어둡게. 하단 내비게이션 바 아이콘이 남색 위에서 보이지 않던 문제와 Android 15에서 키보드가 입력창을 가리던 문제 수정. 라이트 테마 고정
- **아이콘**: 단색 알림 아이콘(`ic_stat_notify`) 및 Android 13+ 테마 아이콘(monochrome) 추가
- **도메인 허용 목록**: 포털 계열 도메인(`util/PortalHosts.kt`)만 앱 안에서 열고, JS 브릿지·카메라/마이크 권한·스타일 주입도 해당 도메인에만 허용. 그 외 링크는 외부 브라우저/앱으로 열림
- **바로가기 링크 자동 동기화**: 설정 모달 바로가기 주소를 포털 화면의 실제 링크에서 읽어와 포털 주소 변경에 자동으로 따라감
- **알림 흐름 개선**: 앱 실행 시 권한 요청을 하지 않고 설정에서 요청. 영구 거부 시 시스템 설정으로 이동하며, 설정 복귀 시 상태가 즉시 갱신됨.

### 1. 포털 디자인 언어 완벽 일체화 & 로딩 화면 고도화 (신규 v1.2.0)

  - 카카오톡 1:1 업무지원 상담 채널
  - 수강생 증명서 발급 시스템 다이렉트 연동
- **앱 환경 관리**: 포털 원클릭 새로고침 및 캐시/세션 초기화 기능, 앱 버전(`v1.7.0`) 자동 연동 표시

### 5. 네이티브 파일 입출력 완벽 연동
- **파일 업로드 (`WebChromeClient.onShowFileChooser`)**: `<input type="file">` 동작 시 **카메라 즉시 촬영(`FileProvider`)**과 **갤러리/파일 탐색기** 동시 지원
- **첨부파일 다운로드 (`PortalDownloadHelper.kt`)**: 세션 인증 쿠키를 안드로이드 시스템 `DownloadManager`에 주입하여 권한이 필요한 첨부파일도 안전하게 다운로드

### 6. Google Play Protect 및 배포 자동화
- **정식 릴리스 서명**: `release-upload-key.jks` (SHA-256) 정식 서명 적용
- **R8 / ProGuard 코드 난독화**: 릴리스 바이너리 경량화 및 앱 무결성 검증
- **패키징 자동화**: 빌드 시 `kcook_wss_v{versionName}.apk` 형식으로 자동 명명

## 🛠️ 빌드 및 패키징 방법

### 개발 환경
- **Android Studio**: Ladybug / Jellyfish 이상 권장
- **JDK**: Java 17
- **Gradle**: 8.9 (Kotlin DSL)
- **Compile SDK**: 36 (Android 16)
- **Min SDK**: 26 (Android 8.0 Oreo)

### 빌드 명령어
```bash
# 1. 정식 릴리스 APK 빌드 (kcook_wss_v1.7.0.apk 생성)
./gradlew assembleRelease

# 2. Google Play Store 배포용 번들 빌드 (app-release.aab 생성)
./gradlew bundleRelease

# 3. 디버그 호환용 APK 빌드 (kcook_wss_v1.7.0_debug.apk 생성)
./gradlew assembleDebug
```

출력 파일 경로:
- Release APK: `app/build/outputs/apk/release/kcook_wss_v1.7.0.apk`
- Release AAB: `app/build/outputs/bundle/release/app-release.aab`
- Debug APK: `app/build/outputs/apk/debug/kcook_wss_v1.7.0_debug.apk`
