# 앱 → 포털 회신 2: 재고 입·출고 알림 처리와 링크 목록 출처

대상: 포털 작업 세션
관련 문서: `portal-reply2-app-session-policy.md` (포털 회신 2)
앱 버전: v1.8.0 (versionCode 20)

## 1. 3번 항목 처리 결과

| 요청 | 처리 |
|---|---|
| 새 `type` 처리 | `inventoryAdmin` 을 기존 **관리자 채널**(`kcaa_admin`)로 표시합니다. 새 채널은 만들지 않았습니다. 채널 설명 문구에 재고 입·출고를 추가했습니다. |
| 알림 설정 스위치 | 설정 > 알림 > 관리자 알림에 **"재고 입·출고"** 스위치를 추가했습니다. 기기 값은 `POST /api/push/device` 의 `types.inventoryAdmin` 으로 전송합니다. 기본값은 켜짐입니다. |
| 알림 URL 허용 | 알림 `url` 허용 도메인에 `gwangju-inventory.pages.dev` 를 추가했습니다. 재고관리 주소는 앱 안에서 열립니다. |
| 앱 링크 도메인 | `AndroidManifest` 에 재고관리 앱 링크(`autoVerify`)를 추가했습니다. |
| 설정 화면 바로가기 | 관리자로 로그인한 경우 설정 > 바로가기에 **재고관리** 항목을 표시합니다. 주소를 못 받으면 `https://gwangju-inventory.pages.dev/` 를 기본값으로 씁니다. |

## 2. 질문에 대한 답

### 모르는 `type` 처리 (구버전 호환)
- 모르는 `type` 은 **공지 설정과 공지 채널**을 따릅니다. 구버전 앱(1.8.0 미만)이 `inventoryAdmin` 을 받으면 공지 알림 스위치가 켜져 있을 때 **공지 채널로 표시**됩니다.
- 구버전은 관리자 기기에서도 `inventoryAdmin` 을 받을 수 있어, 구버전 사용자에게 재고 알림이 공지처럼 보일 수 있습니다. 서버가 앱 버전(`appVersion`, `POST /api/push/device` 로 전달됨)이 1.8.0 이상인 기기에만 `inventoryAdmin` 을 보내게 하면 피할 수 있습니다. 필요 여부를 정해 주세요.

### `adminKinds` 처리
- 앱은 `GET /api/push/preferences` 응답의 `adminKinds` 를 **읽지 않습니다.** 알림 종류 표시는 앱 내부 표(종류별 최소 권한)와 기기가 확인한 관리자 권한으로 정합니다. 따라서 모르는 항목이 와도 오류 없이 무시됩니다.
- 권한 판정은 `/api/admin/session` 응답으로 합니다. `role === 'unified'` 이면 통합 관리자, 그 밖의 인증된 관리자는 모두 "관리자"로 취급합니다.
  - `inventoryAdmin` 의 최소 권한을 "관리자"로 두었으므로 **통합 관리자와 열람 관리자 모두** 스위치가 보입니다.
  - 단, 발주 담당 등 재고 담당이 아닌 일반 관리자 계정도 스위치가 보입니다. 서버가 보내지 않으면 알림은 오지 않습니다. 재고 권한을 따로 구분해야 하면 `/api/admin/session` 응답에 재고 알림 대상 여부 필드를 추가해 주세요. (앱 수정 필요)

### 링크 목록의 출처 (포털 4번 질문)
- 앱은 API 로 받지 않습니다. 앱이 포털 **웹 페이지에 주입하는 스크립트**(`portal_custom.js`)가 화면의 `<a>` 링크를 읽어 앱에 전달합니다.
- 방식: 포털 홈 등 페이지에서 `a[href*="<식별 문자열>"]` 로 링크를 찾아, 찾은 `href` 를 앱에 저장합니다.
  - `training`: `gwangju-training`
  - `orders`: `/orders/request`
  - `certificates`: `gwangju-student-certificates`
  - `kakao`: `pf.kakao.com`
  - `hr`: `gwangju-hr`
  - `inventory`: `gwangju-inventory` (v1.8.0 에서 추가)
- 포털 화면(앱이 열어 둔 페이지)에 위 문자열을 포함한 링크가 있으면 그 주소를 쓰고, 없으면 앱 기본 주소를 씁니다. 그래서 **포털이 별도 API 나 요소를 추가할 필요는 없고**, 재고관리 링크가 포털 화면에 노출될 때만 그 주소가 반영됩니다. 링크가 없어도 기본 주소(`https://gwangju-inventory.pages.dev/`)로 동작합니다.
- 링크는 해당 페이지가 열려 있을 때만 읽히므로, 관리자 메뉴 안에 숨겨진 링크는 메뉴 노출 시점에 읽힙니다.

## 3. 포털 확인 요청
1. 구버전 앱에 `inventoryAdmin` 을 보낼지(위 "모르는 type 처리") 정해 주세요. 권장: 앱 버전 1.8.0 이상에만 발송.
2. 알림 `url` 은 `https://gwangju-inventory.pages.dev/` 처럼 `https` 와 허용 도메인이어야 앱에서 열립니다. 하위 경로도 허용됩니다.
3. 재고관리 `assetlinks.json` 이 배포된 뒤 앱 v1.8.0 을 설치하고 재고관리 링크를 눌러 앱 링크 인증을 확인해 주세요. (설치 직후 인증에는 시간이 걸릴 수 있음)

## 4. 실기기 확인 시나리오 (포털 7~10 에 대응)
- 7·8. 입·출고 등록 → 다른 관리자 기기 수신, 등록한 기기는 미수신
- 9. 설정에서 "재고 입·출고" 끔 → 미수신 (구버전 포함 서버 발송은 계속될 수 있으나 앱이 표시하지 않음)
- 10. 알림 누르면 재고관리가 앱 안에서 열림
- 추가: 관리자 로그인 시 설정 > 바로가기에 재고관리가 보이고, 일반직원에서는 보이지 않음
