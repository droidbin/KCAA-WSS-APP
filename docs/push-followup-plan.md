# 앱 알림 보완 추가 계획 (v1.6.0 이후)

기준: 앱 v1.6.0(`7456a38`), 포털 `e865050`. 포털로 넘길 자료는 `portal-handoff-android-push.md`에 따로 정리했다.

> **진행 상황 (v1.7.0)**: P1(오프라인 관리자 판정), P2(기기 알림이 꺼지면 서버 등록 해제), P3(서버 `role` 반영), P4(발주·증명서 앱 링크)는 v1.7.0에 반영했다. P0 실기기 검증과 P5(선택 개선)는 남아 있다. 포털은 `51bc44c`에서 해제 API, `appVersion`/`notificationsEnabled` 저장, 역할별 관리자 종류, assetlinks 확대를 배포했다.

## 1. 현재 상태 요약

v1.6.0에서 채널 분리, 알림 주소 검증, 서버 상태 확인(`GET /api/push/preferences`), 관리자 스위치 유지, 등록 오류 안내, 발주 알림 기기 연결을 넣었다. 빌드와 릴리스는 끝났지만 **실기기로 수신을 확인한 기록이 없다.**

## 2. 앱에서 할 보완 (우선순위 순)

### P0. 실기기 검증 (코드 변경 없음, 가장 먼저)
- 선행: 포털 운영 환경의 `FCM_SERVICE_ACCOUNT` 설정 확인(포털 요청 1번). 설정 화면에 "알림 발송이 아직 준비되지 않아…" 안내가 뜨면 서버 설정 문제.
- 시나리오: 6종 알림 수신(포그라운드·백그라운드·종료), 종류별 채널 표시, 같은 `tag` 덮어쓰기, 딥링크(포털·발주·증명서 URL, 그 외 URL은 포털 홈), 종류 스위치 off 후 차단, 알림 권한 거부 후 허용, `onNewToken` 재등록, v1.5.0 → v1.6.0 덮어쓰기 설치.
- 관리자: 로그인 → 관리자 스위치 노출 → 로그아웃 → 스위치 숨김 확인. 통합관리자·열람 관리자 각각.
- 통과 기준: 위 항목이 모두 기대대로 동작하고 설정 화면에 오류 안내가 없을 것.

### P1. 관리자 역할 유지 판정의 오프라인 오류 수정 (v1.6.1)
- 문제: `PortalPush.setRole(staff)`가 서버 확인(`fetchServerState`)에 실패(`null`)하면 관리자 역할이 유지되는 것으로 보지 않고 일반직원으로 내림. 네트워크가 잠깐 끊긴 상태에서 설정 화면을 열면 관리자 알림 스위치가 사라지고, 관리자 종류 값이 빠진 채 재등록될 수 있음.
- 수정: 서버 확인이 **실패**(null)하면 현재 권한을 유지하고 다음 기회에 다시 확인. 서버가 `admin:false`를 **명확히 응답**했을 때만 일반직원으로 내림.
- 파일: `push/PortalPush.kt`(`setRole`). 검증: 비행기 모드에서 설정 화면 열기 → 관리자 스위치 유지 확인.

### P2. 알림 끄기·해제 흐름 (포털 API 선행 필요)
- 현재: 앱에서 알림을 꺼도 서버 등록은 남음(해제 API 없음). 시스템 알림이 꺼져 있어도 서버는 계속 FCM을 보냄(`notificationsEnabled`를 서버가 읽지 않음).
- 앱 작업(포털 요청 2·3번 완료 후): 기기 등록 해제 호출 연결, 등록 시 `notificationsEnabled` 반영. API가 없는 동안은 현 동작 유지.

### P3. 관리자 판정 단순화 (포털 요청 4번 완료 후)
- 현재: 앱이 `/api/admin/session`으로 일반/통합 관리자를 구분하고, 서버 `admin`은 유지 여부에만 사용(서버 값이 boolean이라 구분 불가).
- 서버가 `role`(`unified`/`reader`)과 역할별 허용 알림 종류를 알려 주면, 앱이 관리자 세션 API에 의존하지 않고 서버 값으로 스위치를 결정하도록 변경. 앱·웹 이중 정의(`PUSH_SECTIONS`, `TYPE_MIN_ROLE`)도 줄일 수 있음.

### P4. 앱 링크(autoVerify) 확장 (포털 요청 5번 완료 후)
- 현재: 매니페스트 앱 링크 필터는 포털 도메인뿐. `assetlinks.json`이 `deploy/pages-portal`에만 있어 발주·증명서 도메인은 검증 불가.
- 두 사이트에 `assetlinks.json`이 배포되면 매니페스트에 해당 도메인 `intent-filter`(autoVerify) 추가. 알림 탭은 명시적 인텐트라 이 작업 없이도 동작.

### P5. 선택 개선 (필요할 때만)
- 같은 종류 알림 여러 건 묶음 표시(`setGroup` + 요약 알림).
- 설정 화면에서 시스템 채널 설정으로 바로 이동(`ACTION_CHANNEL_NOTIFICATION_SETTINGS`).
- 서버가 `appVersion`을 저장하게 되면 구버전 앱 안내.

## 3. 릴리스 계획
| 버전 | 내용 | 조건 |
|---|---|---|
| v1.6.1 (패치) | P1 수정 + P0에서 나온 버그 | 실기기 검증 후 |
| v1.7.0 (마이너) | P2·P3·P4 중 포털 API가 준비된 항목 | 포털 배포 후 |

## 4. 포털 의존 요약
포털에 요청할 5가지(`portal-handoff-android-push.md` 2장)가 P0, P2, P3, P4의 선행 조건이다. 요청 완료 전에는 앱이 현재 동작을 유지하므로 서로 막히지 않는다.
