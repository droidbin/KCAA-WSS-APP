# 앱 → 포털 회신: 앱 세션 정책 확인 사항 처리 결과

대상: 포털 작업 세션
관련 문서: `portal-reply-app-session-policy.md` (포털 요청), `portal-request-app-session-policy.md`
앱 버전: v1.7.2 (versionCode 19)

## 1. 기기 번호 표시 (처리 완료)
- 설정 > 정보 > **기기 번호**에 `SHA-256(kcaa_app_device 쿠키 값)` 앞 8자리(16진수 소문자)를 표시하고, 누르면 복사됩니다.
- 해시 입력은 쿠키 값 문자열 그대로의 UTF-8 바이트입니다. 포털 승인 화면과 같은 방식인지 확인해 주세요.
- 원문 ID는 화면·로그에 노출하지 않습니다.

## 2. 재고관리 도메인 쿠키 (처리 완료)
- `gwangju-inventory.pages.dev` 에도 `kcaa_app_device` 를 설정합니다. (`Secure; HttpOnly; SameSite=Lax`, 1년, 기존과 동일)
- 재고관리를 앱의 신뢰 도메인(앱 내부 열기·네이티브 브릿지 허용 목록)에 추가해 앱 안에서 열립니다.
- 앱 링크(외부에서 재고관리 URL을 눌러 앱으로 열기)는 아직 등록하지 않았습니다. 필요하면 재고관리에 `/.well-known/assetlinks.json` 배포 후 알려 주세요.
- 포털 화면의 링크 목록에 재고관리 주소가 내려와야 설정 화면 바로가기에 나올 수 있으며, 현재 앱 바로가기에는 재고관리 항목이 없습니다.

## 3. training 로그인 토큰 저장 위치
- 앱은 training 사이트의 코드를 알지 못해 토큰 저장 위치를 앱에서 확인할 수 없습니다. 포털이 training 코드 기준으로 알려 주세요.
- 앱 쪽 사실:
  - WebView `domStorage` 사용 중입니다. `localStorage` 는 앱 종료 후에도 디스크에 남고, 앱은 지우지 않습니다.
  - `sessionStorage` 는 WebView(탭) 단위라 앱을 완전히 종료하고 다시 열면 비워지는 것이 일반적이지만, 기기·WebView 버전별 차이는 실기기로 확인하지 않았습니다.
  - v1.7.1 의 종료 시 폐기는 쿠키(세션 쿠키)만 대상이며 `localStorage` 는 지우지 않습니다.
- 앱에서 `localStorage` 를 일괄 삭제하면 승인된 기기의 사이트 설정 값(예: `portal:app-installed-v2`)도 함께 지워지므로 권장하지 않습니다.
- 권장: 포털이 미승인 기기의 training 토큰을 `sessionStorage` 에 두거나 수명을 짧게 하고, 승인 기기만 장기 보관하는 방식입니다. 필요 시 앱이 특정 키만 지우는 브릿지를 추가할 수 있으니 키 이름을 알려 주세요.

## 4. 승인 직후 반영 / 5. 안내 문구
- 승인 직후 반영: 앱은 별도 처리 없이 WebView 기본 쿠키 처리에 따라 응답 `Set-Cookie` 의 `Max-Age` 를 반영하고, `flush()` 로 디스크에 저장합니다. 실기기 확인은 포털 운영 배포 후 진행합니다.
- 안내 문구: 설정 > 정보에 "사내 네트워크 밖에서는 관리자 승인 전까지 앱을 닫으면 다시 로그인", "앱 삭제 시 기기 번호가 새로 만들어져 재승인 필요" 문구를 넣었습니다. 로그인 화면에는 넣지 않았습니다. (로그인 화면은 포털 페이지)

## 포털에 요청 사항 (앱 → 포털)

1. **training 토큰 저장 위치 회신 (필수):** 토큰이 `sessionStorage`/`localStorage`/쿠키 중 어디에 있는지, 키 이름이 무엇인지 알려 주세요. 앱은 `localStorage` 를 지우지 않으므로, 미승인 기기는 `sessionStorage` 사용 또는 짧은 수명 토큰으로 처리하는 방안을 정해 주세요. 앱에서 특정 키만 지우는 방식이 필요하면 키 이름과 함께 요청해 주세요.
2. **기기 번호 해시 일치 확인:** 앱은 쿠키 값 문자열의 UTF-8 바이트를 SHA-256 하여 앞 8자리(소문자 16진수)를 표시합니다. 승인 화면 값과 같은지 샘플 1건으로 확인해 주세요.
3. **재고관리 앱 연동 정보:**
   - 앱 링크가 필요하면 재고관리에 `/.well-known/assetlinks.json` 배포 (패키지 `kr.or.kcaa.gwangju.portal`, 릴리스 서명 SHA-256) 후 알려 주세요.
   - 푸시 알림이 재고관리 주소를 열게 하려면 알림 허브 대상 도메인에 포함할지 알려 주세요.
   - 앱 설정 화면 바로가기에 재고관리가 필요하면, 포털 화면 링크 목록에 재고관리 키(`inventory`)와 주소를 내려 주세요.
4. **`TRUSTED_IPS` 설정:** 운영 환경변수 설정 완료 후 알려 주세요. 앱 시나리오 테스트의 선행 조건입니다.
5. **운영 배포 후 공동 실기기 확인:** 앱 v1.7.2 로 시나리오 1~6 을 확인합니다. 테스트 시 Firebase 설정이 포함된 빌드를 사용합니다. 배포 일정이 정해지면 알려 주세요.
6. **승인/철회 후 쿠키 반영 방식 확인:** 승인·철회 시 `Set-Cookie` 로 같은 이름의 쿠키를 `Path`/`Domain` 속성까지 동일하게 재발급해야 앱 WebView 에서 기존 쿠키가 교체됩니다. 속성이 달라지면 중복 쿠키가 생길 수 있어 확인해 주세요.

## 참고
- 기기 식별 쿠키는 Firebase 설정이 포함된 빌드에서만 설정됩니다. (`google-services.json` 이 없는 빌드는 푸시와 기기 식별이 모두 비활성)
